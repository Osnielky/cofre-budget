# App Speed Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut the per-call API floor (~250 ms alone, 600–1,100 ms under a page's 7–10 parallel calls), stop re-downloading the same data on every navigation, and shrink what each page ships.

**Architecture:** API side: indexes on the hot columns, a slimmer transaction row, no recurring materialiser or user lookup on every call, boot sweeps off the cold-start path, GROUP BY aggregates where the service looped. Web side: SWR as the one client cache (stale-while-revalidate, shared keys across pages), lazy loading for code only some users reach, a shared authenticated layout so the sidebar stops remounting. Deploy: CPU boost and an explicit pool.

**Tech Stack:** NestJS 11 + TypeORM (Postgres; sqlite in tests), Next.js 16 + React 19, SWR, Vitest, Cloud Run.

**Spec:** The investigation summary in chat on 2026-11-07 (measurements at budgetcofre.com; audits of `apps/web/src`, `apps/api/src`, `deploy/`). Numbers quoted there are the baseline.

## Global Constraints

- `synchronize` stays off; every entity change ships with a migration listed in `apps/api/src/migrations/index.ts`; `migrations.test.ts` must keep passing (it diffs migrations against entities).
- `apps/api/tsconfig.app.json` excludes `*.test.ts`; test files never enter the bundle.
- Never log bodies, tokens, emails or amounts.
- Components consume theme variables only.
- Each task ends green: `npm run test:api`, `npm run test:dashboard`, `npx tsc --noEmit -p apps/web/tsconfig.json`.
- One commit per task on `dev`; do not push until the user says so (the last push already deployed the motion fix).

## Review Focus

- A user who upgrades their plan must not be stuck on the old plan for longer than the user-cache TTL (30 s); writes through `UsersService` invalidate at once. Test in Task 6.
- Reports asks for up to 20,000 rows; the server clamp must not truncate it. Test in Task 4.
- After logout and login as someone else, no cached list from the first user may paint. Test in Task 10 (cache cleared on `clearUser`).
- The demo owner must still exist before the first login after a cold start; only the sweeps move off the boot path. Test in Task 7.
- A budget whose category is `income` sums positive amounts; a project-category budget matches on `projectId + projectCategoryId`; both must survive the GROUP BY rewrite. Test in Task 8.
